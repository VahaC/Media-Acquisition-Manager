## Highlights

**Reach the app from a script with an access token.** Your **Profile** page has a new **Access
tokens** card: create a token, give it a name such as "Backup script", and send it in the
`Authorization` header of your requests, and the app answers as it answers you in the browser — your
library, your searches, your jobs. The token is shown once, with **Copy**; the app keeps only a
fingerprint of it. See [Access tokens](#access-tokens).

**Read only, or Read and download.** A **Read only** token reads what you can read: the library,
searches, your jobs, the duplicates and your recommendations. A **Read and download** token also sends
a release, cancels following a job and marks a recommendation Not interested. No token ever replaces
or removes a copy, changes a setting, or touches your password or your tokens. See [What a token can
do](#what-a-token-can-do).

**Ask an AI assistant to find and send a release.** Connect Claude Code or Claude Desktop to the app
with a token and ask in plain words, such as "find Interstellar in 4K with Ukrainian audio": the
assistant looks in your library first, searches the release sources, shows what the Download dialog
would pick, and sends only the release you confirm, asking you before every send; it follows your
jobs and reads your duplicates and recommendations too. With a **Read only** token it only reads. The
token's dialog gives you the line to connect each assistant. See [Connect an AI
assistant](#connect-an-ai-assistant).

**You decide how long a token lives, and end it at once.** A token expires after 30 days, 90 days, a
year, or never, and **Revoke** on Profile stops it with its next request. See [Keeping a token
safe](#keeping-a-token-safe).

**The owner sees everyone's tokens and can end them.** The **Users** page counts each user's active
tokens and has a **Revoke tokens** action; resetting a user's password or disabling the user ends
their tokens too. See [For the owner](#for-the-owner).

**Use the app in Ukrainian.** Every page of the web app now speaks Ukrainian as well as English.
Pick yours on **Profile** → **Language** — **As in the browser**, **English** or **Українська** —:
it is saved with your account, so every browser and device you sign in from follows it. See [Your
language](#your-language).

**Choose the language of the catalog.** As the owner, you pick the language the app asks TMDb in,
in the TMDb integration: titles, overviews and posters on the **Recommendations** page and in the
TMDb link dialog come in it wherever TMDb has them. An installation that already had TMDb keeps
Ukrainian. See [The catalog's language](#the-catalogs-language).

**What changes by itself, and what waits for you.** A browser that prefers Ukrainian now shows the
app in Ukrainian straight away, because **As in the browser** is everyone's choice until they pick
another; pick **English** on Profile to keep English. Everything else waits for someone: a token is
created only on purpose, by its own user, and the catalog's language stays as it was until the owner
changes it. See [Turning it on](#turning-it-on).

### Also in this release

- **Changing your own password keeps your tokens** — **Change password** on Profile still signs out
  your other devices, and now says "Your access tokens keep working." Revoke a token you no longer
  trust on its own. See [Keeping a token safe](#keeping-a-token-safe).
- **The owner's password reset and Disable end the user's tokens** — as they end the user's sessions.
  The owner's reset of his own password ends his own tokens too, enabling a user again brings none
  back, and **Disable** asks first when the user has any. See [For the owner](#for-the-owner).
- **The server's messages are still in English** — an error after a failed save, or why a job
  stopped, reads in English in the Ukrainian app until a later update, and these notes stay English.
  See [Your language](#your-language).

## Access tokens

Open your user menu → **Profile** → **Access tokens** → **Create token**, and fill in:

- **Name:** what the token is for, such as "Claude on the laptop" — at most 100 characters.
- **Access:** **Read only** ("Reads the library, searches, jobs, duplicates and recommendations.") or
  **Read and download** ("Also sends downloads (Keep both), cancels following and marks Not
  interested.").
- **Expires:** in 30 days, 90 days (the default), 1 year, or never.

The dialog then shows the token — `mam_pat_` and 43 more letters, digits, `-` and `_` — once. Copy it
now: it won't be shown again, and the app can't show it later, as it keeps only a fingerprint it can
check a token against. Lost it? Revoke it and create another.

On a plain-HTTP address the browser doesn't let the page use the clipboard directly, so **Copy**
copies another way; if even that fails, the dialog asks you to select the token and press Ctrl+C.

Send it as a bearer token, like this — your jobs, as the **Jobs** page lists them:

```bash
curl -H "Authorization: Bearer mam_pat_…" http://<mam>:8118/api/downloads
```

Your tokens are listed on the card, newest first: each one's name, its first characters
(`mam_pat_AbC123…`), its access, when it was created, when it was last used (updated at most once a
minute) and when it expires. An expired token stays in the list, marked **Expired**, until you revoke
it; a revoked one leaves the list.

With a **Read and download** token a script can go the whole way: search (`POST /api/searches`), read
the releases found, send one (`POST /api/downloads`) and stop following the job
(`POST /api/downloads/{id}/cancel`). The README's "Scripts and the API" section shows each step with
`curl` and the answer to expect, and its API surface lists every endpoint.

## What a token can do

A token acts as you, with no more than you may: a member's token reads that member's own jobs and
searches, never anyone else's, and what only the owner may read stays the owner's.

- **Read only:** everything you read in the web app — the library and its sources, the duplicates,
  your searches (searching included, though a search is a POST), your jobs and their files, your
  recommendations and what the Download dialog would offer.
- **Read and download:** all of that, plus three things: send a release found by one of your
  searches, always as Keep both; cancel following one of your jobs; mark a recommendation Not
  interested.
- **Never, whatever its access:** schedule a replacement, remove a copy into the quarantine, restore
  or delete permanently, start a sync, a scan or a recomputation, change or even read the owner's
  settings (Users, Integrations, Media folders, Destinations), change your password, read your session,
  or create, list or revoke tokens. Undoing Not interested stays in the web app too. Every request the
  app adds later stays closed to tokens until it is opened on purpose.

A refused request answers 403 with a sentence that says what to do instead — for a **Read only**
token's send: "This access token is read only. To send downloads, cancel following or mark Not
interested from a script, create a token with “Read and download” access on your Profile page; see
“Scripts and the API” in the README." A job that also replaces one of the owner's copies is cancelled
on the **Jobs** page, never with a token.

A token that is wrong, revoked or expired, or whose user is disabled or deleted, gets the same answer
as a request with no token at all: 401, "Sign in to continue."

## Connect an AI assistant

An AI assistant talks to the app through its MCP endpoint, `/mcp`, with one of your tokens, and does
what that token may do, as you. **Claude Code** connects to it directly, and **Claude Desktop**
through a small bridge, `mcp-remote`, that runs on the same computer. The assistant's computer has to
reach the app, so this works at home or over a VPN into your home network; claude.ai and the Claude
phone app can't connect, as they call from Anthropic's cloud.

1. Create a token as above: **Read only** if the assistant should only look, **Read and download** if
   it may also send releases, cancel following and mark Not interested.
2. Before you press **Done**, copy the line for your assistant from **Connect an AI assistant**,
   under the token. Both lines hold the whole token and the address you opened the app at, so open
   it at the address the assistant's computer uses.
3. **Claude Code:** run the command once in a terminal. It looks like this, with your address and
   token:

   ```bash
   claude mcp add --transport http --scope user mam http://<mam>:8118/mcp --header "Authorization: Bearer mam_pat_…"
   ```

   `--scope user` makes the app available in all your projects. `/mcp` in Claude Code then shows
   `mam` as connected.
4. **Claude Desktop:** paste the configuration into `claude_desktop_config.json` — **Settings** →
   **Developer** → **Edit Config** opens it; if the file already has `mcpServers`, put the `mam`
   entry inside it. Claude Desktop from the Microsoft Store reads
   `%LOCALAPPDATA%\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Roaming\Claude\claude_desktop_config.json`
   instead, so put it there. It needs Node.js 18 or later. Then quit Claude Desktop and start it
   again.

Then just ask: "Do we have Dune?", "Find The Bear season 3 in 1080p with Ukrainian audio", "What are
my downloads doing?", "What could I clean up in the duplicates first?". The assistant has twelve
tools: it searches your library and the release sources, lists one search again filtered without
searching again, shows what the Download dialog would offer and whether the destination can be
checked for files a release would write over, and — with **Read and download** — sends a release,
always as Keep both, stops following a job (the torrent stays in your download client) and marks a
recommendation Not interested. It reads your jobs, the duplicates — the biggest space savings first,
if you ask — and your recommendations, and what you could see in the web app; a member's assistant
sees that member's own jobs and searches only.

Claude Code asks you before it uses a tool you haven't allowed, and **always** before a send, even
when you allowed the app's tools. The assistant is told to send only the release you confirmed.
Nothing else is in its reach: no tool replaces or removes a copy, restores or deletes from the
quarantine, or reads or changes a setting, a user or a token — those stay in the web app.

A token may make 60 requests a minute to `/mcp`; a conversation needs far fewer. When a token is
revoked or expires, the assistant stops connecting ("Sign in to continue."): create a new token and
replace the old one in the assistant's line or configuration. The README's "Connect an AI assistant
(MCP)" section has the details, the Claude Desktop configuration and what each failure looks like.

## For the owner

The **Users** page (**Users** in your user menu) has an **Access tokens** column with each user's
number of active tokens — not revoked, not expired. **Revoke tokens** on a user's row ends every one
of them at once, after a confirmation; it waits with "No active tokens." when there is none. Each user
still sees and revokes their own tokens on Profile; you never see anyone's token, only the count.

**Reset password** now also ends the user's access tokens — yours too when you reset your own —, and
so does **Disable**, so enabling the user again brings back neither their sessions nor their tokens.
That's why **Disable** now asks first when the user has active tokens, saying how many it revokes; a
user without any is disabled at once, as before. Deleting a user deletes their tokens with them. Each
token created, revoked — by whom — or refused is in the audit trail.

## Keeping a token safe

- **A token is a password for its access.** Keep it out of shared files and screenshots, give each
  script its own, and pick **Read only** unless the script sends downloads.
- **The app speaks plain HTTP**, so a token crosses your network as it is, like your password. Use
  it on a network you trust, or behind a reverse proxy that adds HTTPS, and revoke a token you think
  someone saw.
- **Wrong tokens count against the sign-in limit.** Sign-in attempts, successful or not, and wrong
  tokens share one limit of ten a minute per address. Once it is used up, for the rest of that minute
  every request from that address with a token to the app's data answers 429, "Too many attempts.
  Wait a minute and try again.", a good token included. Behind a reverse proxy every client shares
  one address, so a script left running with a revoked token keeps the whole household from signing
  in: fix or stop the script.
- **An assistant's line holds the whole token.** Claude Code keeps it in `~/.claude.json`, Claude
  Desktop in `claude_desktop_config.json`, and the command stays in your terminal's history: keep
  those files to yourself, never add the app to a project's shared `.mcp.json`, and give each
  assistant its own token, so revoking one leaves the others working.
- **Changing your own password keeps your tokens.** When a token may have leaked, revoke it on
  Profile; when your password may have, change it and look through your tokens too: someone signed in
  as you could have created one.

## Your language

Open your user menu → **Profile** → **Language**, under **Appearance**, and pick one:

- **As in the browser** (where everyone starts): the app speaks the first of your browser's
  preferred languages it has, Ukrainian or English, and English when it has none of them.
- **English** or **Українська**: the app speaks that language on every browser and device you sign
  in from, whatever the browser prefers. The two are named in their own language, so you find yours
  whichever language the page is in.

Your choice is saved with your account at once — there is no Save button — and the page switches to
it straight away. Your other tabs of the app in the same browser switch with it; a tab open on
another device follows within about a quarter of an hour, as soon as you open **Profile** there, or
when you next sign in there. While a new access token is on screen, the page waits for you to close
it before it switches, so you don't lose the token. Before you
sign in, and after you sign out, the sign-in page follows the browser, as it doesn't know you yet.

Dates, numbers and file sizes are written the way your language writes them. With English, your
browser's own English decides, so a British browser keeps its day-first dates.

What stays as it was:

- **The server's messages are still in English** for now: the sentence after a failed save, why a
  job stopped or a check failed, a run's error. A later update brings them in your language.
- **Names are as their source has them**: library titles as Jellyfin keeps them, release names as
  the source lists them, and TMDb's titles in the catalog's language, which the owner chooses (see
  [The catalog's language](#the-catalogs-language)).
- **These release notes** are in English only.

## The catalog's language

The **Recommendations** page and the TMDb link dialog show what TMDb says about a film or a show:
its title, overview, poster, genres, collection and people. As the owner, you choose the language
TMDb is asked in: your user menu → **Integrations** → **Edit** on the TMDb row → **Catalog
language**, then **Save changes**. Every language TMDb keeps translations in is offered, Ukrainian
and English first. Where TMDb has no translation of a work in that language, you get the original.

- **An installation that had TMDb before keeps Ukrainian**, and nothing is read from TMDb again for
  the update.
- **A TMDb you add now** starts at the language you use the app in; change it in the same dialog
  before you press **Add integration**.
- **After a change**, the app reads the catalog again in the new language at once, in the
  background: the **Recommendations** page shows how far it has got, and the TMDb link dialog's
  suggestions follow without being searched for again. Only what was read in another language is
  read again, and the release sources' newest releases of the last two weeks that matched nothing
  are matched again in the new language.
- **The Description on a recommendation card is yours**: it comes in the language you use the app
  in, Ukrainian or English, whatever the catalog's, and in English where TMDb has nothing in yours.
- **A TMDb link you already set** keeps the title it was set with until you set it again.
- **With a language other than Ukrainian**, the check of what the release sources carry finds a
  Toloka release by its original title, as its Ukrainian title no longer matches the catalog's; a
  film whose original title isn't in Latin letters, such as a Japanese one, is then not found on
  Toloka at all. Pick the language your release sources name films in.

The **Integrations** list shows the catalog's language under the TMDb row.

## Turning it on

Nothing to switch on: every signed-in user has the **Access tokens** card and the **Language** card.

**Your language:** user menu → **Profile** → **Language** → **As in the browser**, **English** or
**Українська**. It is saved as you click.

**An access token:**

1. Open your user menu → **Profile**, and under **Access tokens** press **Create token**.
2. Fill in **Name**, **Access** and **Expires**, and press **Create token**.
3. **Copy** what you need before you press **Done**: the token, kept where your script reads it, or
   the Claude Code command or the Claude Desktop configuration under **Connect an AI assistant**.
4. Call the app with it: `curl -H "Authorization: Bearer mam_pat_…" http://<mam>:8118/api/downloads`
   lists your jobs.
5. For an AI assistant, run the Claude Code command in a terminal, or paste the Claude Desktop
   configuration into `claude_desktop_config.json` and restart Claude Desktop, as [Connect an AI
   assistant](#connect-an-ai-assistant) says; then ask it something, such as "What are my downloads
   doing?".

As the owner, the **Users** page shows each user's count and **Revoke tokens** from the start.

**The catalog's language (the owner):** user menu → **Integrations** → **Edit** on the TMDb row →
**Catalog language** → **Save changes**. Leave it alone to keep what you have: Ukrainian on an
installation that had TMDb before.

## Your files

Creating a token writes one row to the app's database, `mam.db`: its name, its access, when it was
created and expires, its first characters and a SHA-256 fingerprint of it — never the token itself.
Using it updates when it was last used, at most once a minute. The data backup keeps them with the
accounts. For the tokens, the only change to the database is that one new table; nothing that was
there before changes, and nothing is written to your media folders or download client.

Connecting an AI assistant changes nothing in the database. What the assistant then does is written
as the web app writes it, in your name: a search kept for a day, a job for each release it sends, a
Not interested mark.

The languages add a few columns to `mam.db` as the app starts after the update, and change no table
otherwise: your account's language, empty until you pick one, so you follow the browser; the TMDb
integration's catalog language, set to Ukrainian on an integration you already had; and, on the
catalog's cached titles and names, the language each was read in, marked Ukrainian for everything
read before, which it was. Saving your language writes only that column; it adds nothing to the
audit trail. A change of the catalog's language is recorded there as a change of the integration.
Nothing is written to your media folders, Jellyfin or your download client.
