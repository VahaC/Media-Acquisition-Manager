## Highlights

**Use Transmission instead of qBittorrent.** The **Integrations** page adds a download client of the
type **Transmission**, 4.0 or newer. Everything the app did with qBittorrent it now does with
Transmission: it lists where a download can go, sends a release, follows it on the **Jobs** page until
it is done, checks before a send that the release would land on no other file, and, once you turn
replacement on, replaces an old copy through the quarantine with the same checks as before. Run one of
the two: Transmission takes qBittorrent's place, it doesn't sit beside it. See [Transmission instead of
qBittorrent](#transmission-instead-of-qbittorrent).

**Your library folders are Transmission's destinations.** Transmission has no categories, so a
destination for it is a folder: each Jellyfin library's folder, as Transmission sees it through the
path mappings of its integration, and Transmission's own download folder. Transmission confirms each
one each time the list is read. A library folder it can't see stays in the list with what to do about
it, never hidden. See [Destinations for Transmission](#destinations-for-transmission).

**One add per send, into the folder, with the destination's name as its label.** A film sent to
**Movies** shows in Transmission in, say, `/downloads/movies` with the label "Movies", started, whatever
Transmission does with the torrents it is given by default. See [Sending to
Transmission](#sending-to-transmission).

**Use Jackett instead of Prowlarr.** Jackett's Toloka feed is a Torznab feed like Prowlarr's: add it
under **Integrations** as a **Torznab** integration with the address its **Copy Torznab Feed** gives.
Searches, the Search page's matches, Recommendations and the destination a release's tracker section
picks work as they did with Prowlarr. A refused key or a wrong address now says where to fix it. See
[Jackett instead of Prowlarr](#jackett-instead-of-prowlarr).

**The Search page reads a release's description too.** A Ukrainian-only release whose title Jackett or
Prowlarr left as punctuation — "« » (2026) WEB-DL-AVC …" — now matches your copy by the Ukrainian title
and year in its description, as Recommendations already did. See [Matches from the
description](#matches-from-the-description).

**Transmission and Jackett stay off until you add them.** An installation that keeps qBittorrent and
Prowlarr sends, follows and replaces as it did; what it sees change is listed under [Also in this
release](#also-in-this-release). Moving to Transmission takes a few settings in Transmission first, and
retiring qBittorrent takes care while its torrents still seed your library's files. See [Turning it
on](#turning-it-on).

## Transmission instead of qBittorrent

Add it as the owner, under the user menu → **Integrations** → **Add integration** → **Transmission**:

- **Address:** the address of Transmission's web interface, such as `http://192.168.1.10:9091`. The
  app adds `/transmission/rpc` itself; an address that already ends in `/transmission/rpc`,
  `/transmission` or `/transmission/web` works too.
- **User name and password:** the ones Transmission asks for (`USER` and `PASS` in the linuxserver.io
  image). Stored encrypted, like qBittorrent's password, and never shown again.
- **Path mappings:** how Transmission's folders map onto the app's, `/downloads` → `/media` if
  Transmission sees your media at `/downloads` and the app at `/media`. For Transmission they also work
  the other way: they are how the app finds Transmission's name for each library folder. See
  [Destinations for Transmission](#destinations-for-transmission).

**Test connection** answers "Connected to Transmission 4.1.3." when all is well. Otherwise it says what
Transmission did and how to fix it:

- an older Transmission: "This is Transmission 3.00; the app needs Transmission 4.0 or newer. Update
  Transmission, then test again.";
- a wrong user name or password: "Transmission refused the user name or password.";
- no user name while Transmission asks for one: "Transmission asks for a user name and password. Enter
  them under Integrations.";
- the app's address not allowed: "Transmission refused this app (403 Forbidden): this app's address
  isn't on its RPC whitelist (WHITELIST in the linuxserver image, rpc-whitelist in its settings), or it
  locked its RPC after too many wrong passwords, which only a restart of Transmission ends.";
- a host name Transmission doesn't accept, which it checks only while it has no password: "Transmission
  doesn't accept the host name in this address (421 Misdirected Request); it checks host names only
  while it has no password. Give Transmission a user name and password (USER and PASS in the linuxserver
  image), add the host name to its rpc-host-whitelist (HOST_WHITELIST), or use its IP address, then test
  again.";
- an address where Transmission isn't: "Transmission's RPC wasn't found at this address (404 Not Found).
  Use the address of Transmission's web interface, such as http://192.168.1.10:9091.";
- its temporary folder switched on: "Transmission keeps unfinished downloads in its temporary folder
  “/downloads/incomplete”, where the app can't follow them. In Transmission's web interface open Edit
  Preferences, Torrents, untick “Use temporary folder”, then test again."

The last one isn't only the test's: while "Use temporary folder" is ticked, the app reads
Transmission's settings and asks it nothing more — no destination, no send, no following —, and every
job sent to it shows why until you untick it.

**A refused password isn't sent again.** With its anti-brute-force setting on, Transmission counts
every refused password towards locking its RPC, and only a restart unlocks it. So once Transmission
refuses the user name and password, or the app itself (403), the app doesn't ask it again until you
change them under **Integrations** or a connection test with them works — or until the app restarts,
an update included, as it keeps that in memory: then it asks once more —, and every page that needed
Transmission says so: "Transmission refused the user name or password the last time the app used them,
so the app won't send them again: with its anti-brute-force setting on, every refusal counts towards
locking its RPC. Correct them under Integrations, or test the connection there once Transmission accepts
them."

**A test that works doesn't prove a password is set.** Transmission without a password takes any user
name and password. Set `USER` and `PASS` in its container, then test.

## Destinations for Transmission

The owner adds them on the **Destinations** page, as for qBittorrent. Pick Transmission in **Add
destination**, and **Folder** lists what Transmission can save to:

- **each library folder of yours**, by the libraries it holds — "Фільми — /downloads/movies" —: the
  folder Jellyfin reports for each library, brought into the app through the Jellyfin integration's
  path mappings, as before, then back into Transmission's paths through the Transmission integration's
  mappings. With `/downloads` → `/media` on Transmission, Jellyfin's `/media/movies` is
  `/downloads/movies`;
- **Transmission's own download folder** — "Transmission's download folder — /downloads/complete" —,
  for downloads that go nowhere near your library. Outside the libraries a replacement can't go
  through it; when it is one of your library folders, it is listed once, as that library's —
  "Фільми, Transmission's download folder — /downloads/movies" —, and when it lies inside one, it is
  named by the library that holds it, and a replacement can go through it as through that library's
  own folder.

Transmission confirms each folder by its free space, each time the list is read. A folder it can't see —
not mounted into its container, or not there at all, which look the same to it — stays in the list,
greyed out and marked "(can't be used)", and Transmission's reason is listed under the field:
"Фільми: Transmission can't see “/downloads/movies” (No such file or directory). Mount that folder into
Transmission, or add a path mapping on this integration that leads there, then look again." A library
the mappings can't lead back to is listed there too, with what to do: "Фільми: “Transmission” has no
folder for the library “Фільми”: none of its path mappings leads to “/media/movies”. Add one under
Integrations, “Transmission”, Path mappings (for example /downloads → /media), then look again." On
the **Destinations** page a saved destination whose folder Transmission no longer sees shows "Not seen
by the client". Jellyfin's Collections library, which holds no media files of its own, is never
offered.

You can only pick a folder Transmission confirmed: the app sends Transmission no folder of its own, and
you can't type one. The destination keeps the folder as Transmission names it and checks it again every
time it is shown, sent to or used for a replacement; editing a destination lists its own folder too,
even once no library leads there any more. The Destinations page names the column **Folder**
when every destination is Transmission's, **Category** when every one is qBittorrent's, and **Category
or folder** for both.

**A destination's name is Transmission's label for the torrent,** so it can't hold a comma, which
Transmission refuses in a label. The dialog says so under the name, and Save refuses one: "“Transmission”
shows this destination's name as the torrent's label, and a label can't contain a comma. Pick a name
without one."

Removing a Transmission destination, or the Transmission integration, changes nothing in Transmission:
the torrents already sent keep their folder and label.

## Sending to Transmission

**Download** works as it did. Once you press **Send**, the app adds the release to Transmission once:
the release, the destination's folder, the destination's name as the torrent's only label, and "start
it now", so a send never waits paused, even when Transmission is set not to start the torrents it is
given. A release the app sends is never sent twice: when Transmission's session ran out at that very
moment, it answers without having read the request, and the app sends that one request once more with
the new session, as only then is it safe.

Before it sends, the app refuses what Transmission can't take or would get wrong, and nothing reaches
Transmission then:

- **a folder Transmission can't see any more:** "“Transmission” can't use the folder of the destination
  “Movies” any more, so nothing was sent. The owner checks the destination under Destinations in
  the user menu.";
- **a torrent that is BitTorrent v2 only**, which Transmission 4.0 and 4.1 can't add: "“Transmission”
  can't take a torrent that is BitTorrent v2 only, which this release is, so nothing was sent.";
- **a release that would land on another file already in the folder**, as with qBittorrent: "“Transmission”
  would write over “Film.2001.mkv” in the folder of the destination “Movies”: a file of another size is
  already there, so nothing was sent." Transmission has one way of laying out a torrent — a lone file
  straight in the folder, several files in a folder named after the torrent —, and cleans file names its
  own way, depending on its version and the system it runs on; the app looks at every place each of
  those ways could give, and at the place of an unfinished file, `<name>.part`, too. A torrent whose
  file names aren't text the app can follow — bytes that aren't UTF-8 in a torrent of several files,
  say — goes without that check, so, as with a magnet, it could land on a file of the same name already
  in the folder; the job says it wasn't checked, and it isn't sent at all when it would replace a copy.

The **Download** dialog warns before **Send** when a Transmission destination's folder can't be
checked: a folder Transmission can't see takes nothing at all, so **Send** waits there until the owner
fixes the destination, under **Keep both** and **Replace after verification** alike; one with no path
in the app takes the release without the check.

**A torrent Transmission already has** is not added again. As with qBittorrent, the app asks
Transmission for the release before it sends, and refuses it then: "“Transmission” already has this
torrent, so nothing was sent." Should Transmission get the same torrent between that question and the
add, it adds nothing and changes nothing about the one it has, and the job fails with where that
torrent really is: "Transmission already has this torrent, in “/downloads/movies” with the label
“Movies”, so it added nothing."

**Members see the destination, never its folder.** The **Download** dialog's summary names the
destination alone, a member's job shows where it went by the destination's name, and every sentence a
member can read names the destination. The owner's job page shows "Movies — folder “/downloads/movies”",
a member's "Movies".

## Following and replacing

The **Jobs** page follows a Transmission download as it follows a qBittorrent one, by the torrent's hash,
never by Transmission's own number for it, which changes when Transmission restarts. A download is
`Downloaded` once Transmission has all of it: its metadata and every wanted byte, whatever its
"finished" flag says (Transmission sets that one only when seeding stops). While Transmission checks a
torrent's files, the job waits; a tracker's warning or error doesn't stop it; a disk error shows on the
job until it clears.

Replacement, the quarantine, **Retry**, **Restore** and **Delete for good** work as they did, through
the same checks. The app reads which of your files a Transmission torrent holds, as it reads
qBittorrent's, and a copy a torrent still holds waits until you remove that torrent in Transmission
without its files. An unfinished file Transmission names `<name>.part` counts as the torrent's too: it
never moves into the quarantine with an old copy beside it. A job whose downloads can't be told apart
now names its client: "“Transmission”'s downloads couldn't be told apart for this release, so the app
can't follow it to verify the new file."; and the Jobs page's "Fix it in Jellyfin or Transmission, then
press Retry" names the client the job used.

## Jackett instead of Prowlarr

Jackett serves Toloka as a Torznab feed, as Prowlarr does, and its answers carry the same titles,
descriptions and sections, so the app reads them the same way:

- the Search page finds and matches the same releases, films, series with their seasons, and cartoon
  series by their Ukrainian titles;
- **Recommendations** count what Jackett carries of a recommended work;
- a release's tracker section still picks the destination the **Download** dialog offers first, from
  Jackett's sections — map them again on the **Destinations** page if you move from Prowlarr, as each
  feed keeps its own;
- a release's download link stays on the server, as Prowlarr's did.

When something is wrong, the sentence now says where to fix it, Jackett or Prowlarr alike:

- a refused key: "The Torznab feed refused the API key (error 100: Invalid API Key). Copy the API key from
  the dashboard of the service that serves this feed, such as Jackett or Prowlarr, into this integration
  under Integrations.";
- an indexer the feed doesn't serve: "The Torznab feed doesn't serve what this address names (error 201:
  Indexer is not supported). Check the indexer in the feed's address, such as
  …/indexers/toloka/results/torznab/ for Jackett or …/1/api for Prowlarr.";
- nothing at the address: "Nothing answers Torznab at this address (404 Not Found). Use the feed's Torznab
  address: Prowlarr's ends in /api, and Jackett's Copy Torznab Feed gives one ending in /results/torznab/."

**Leave "Strip Cyrillic Letters" ticked.** Jackett's Toloka indexer has it ticked when you add it, and
that is the one way the app supports: it reads Toloka's whole title from a release's description, which
the box leaves alone. An answer with the box unticked was never recorded.

A search for a show by its Ukrainian-only title found nothing through Jackett when its answers were
recorded on 2026-10-13, while the same show was among Prowlarr's newest releases. That is Toloka's or
Jackett's own search, which the app can't change.

## Matches from the description

The Search page used to match a release by its title alone. Jackett and Prowlarr keep the English part
of Toloka's title, and of a Ukrainian-only release nothing but punctuation, so such a release matched
nothing. Now each release is read twice, from its title and from its description, which holds Toloka's
whole title, Ukrainian first — the way Recommendations already read it.

- The description adds a match only by an id or by a title **and** a year, as Recommendations count one.
  A title alone is a possible match only when it is the release's own title.
- A copy matched both ways keeps the stronger match, and the title's when they are equal.
- For a series, the episodes the app counts as held, and the episodes a replacement offers, come from
  whichever of the two matched — or from the other when that one names no season or episode.
- **Details** shows both readings, under "Read from the title" and "Read from the description".

## Turning it on

Nothing of Transmission's or Jackett's is switched on for you: an installation that keeps qBittorrent
and Prowlarr sends, follows and replaces as before, with the changes [Also in this
release](#also-in-this-release) lists and the Search page's [matches from the
description](#matches-from-the-description).

### Jackett

1. Add the **Toloka.to** indexer in Jackett with your Toloka account, and leave its **Strip Cyrillic
   Letters** ticked.
2. On Jackett's dashboard, **Copy Torznab Feed** on that indexer gives an address such as
   `http://192.168.1.10:9117/api/v2.0/indexers/toloka/results/torznab/`.
3. In the app, user menu → **Integrations** → **Add integration** → **Torznab**: that address, and the
   **API Key** from the top of Jackett's dashboard. **Test connection**, then **Save**.
4. On the **Destinations** page, tick in each destination the Toloka sections that should go there.

### Transmission

Before you add it, set Transmission up so the app can follow what it sends:

1. **Untick "Use temporary folder"** in Transmission's web interface → **Edit Preferences** →
   **Torrents** — the linuxserver.io image ships it ticked. Do it before anything is sent, and never tick
   it again while downloads run: a download that started there moves into its folder only once it is
   done, which no answer of Transmission's shows.
2. **Give it a user name and password** — `USER` and `PASS` in the linuxserver.io image. Without one,
   Transmission takes any password.
3. **Let it reach your library folders, and write there.** Mount the folder that holds your libraries
   into Transmission — at `/downloads`, say —, and run it as their owner — the same `PUID` and `PGID` as
   your media, 1000 and 100 on the reference setup. If it answers 403, add the app's address to
   `WHITELIST`.
4. **Add it in the app**, user menu → **Integrations** → **Add integration** → **Transmission**: its web
   interface's address, the user name and password, and a path mapping from Transmission's folder to the
   app's — `/downloads` → `/media`. **Test connection**, then **Save**.
5. **After upgrading, sync your Jellyfin library once** — **Library** page, **Refresh all** — so its
   Collections library leaves the folder list: until that sync the app keeps the folder an older version
   stored for it, and the destination's dialog lists it as a library Transmission has no folder for.
6. **Add its destinations** on the **Destinations** page: one per library folder you download into,
   named as you want the label to read.

### Moving from qBittorrent

Phase D runs one download client: Transmission takes qBittorrent's place. To get there safely:

- **Once Transmission's destinations are there, remove qBittorrent's** on the **Destinations** page,
  so the **Download** dialog offers Transmission alone. Don't send to both: the check before a send
  looks only at the client the release goes to, so a qBittorrent torrent still queued, or still
  fetching its metadata, for a place in a library folder is invisible to a send to Transmission, and
  the other way round.
- **Keep the qBittorrent integration switched on.** Before an old copy moves into the quarantine, the
  app asks every download client whether a torrent holds it, whatever destinations it has, and one that
  is switched off can't answer, so every move stops for review until it can. Switched off, it also
  stops following every job sent to it.
- **Remove it under Integrations only once no qBittorrent torrent seeds a file in your libraries, and
  no job sent to it is on the In progress or Needs you tab of the Jobs page** (each user's page lists
  their own jobs). A job still followed when its client is removed stops for good: "The download
  client “qBittorrent” was removed, so this download can't be followed. Cancel the job to stop tracking
  it." The jobs sent to it keep their names.
- Move to Jackett the same way: add Jackett, map its sections on the **Destinations** page, then remove
  the Prowlarr integration, which takes its section mappings and the newest releases it gave
  Recommendations with it.

## Your files

Adding Transmission writes nothing anywhere. Each time its destinations are listed, the app asks
Transmission for its settings and for the free space of each folder, and nothing else. Each send is one
add of the release you sent, into the destination's folder, with its label; the app never stops,
removes, moves or relabels a torrent, and never changes a Transmission setting. Following a download,
and the checks of a replacement, only read Transmission's torrents and their files.

Transmission writes the download straight into the library folder you picked, as qBittorrent writes
into its category's folder; before it sends, the app makes sure no other file is already where the
release would land. What the app itself writes to your media folders is unchanged: the quarantine, and
nothing else.

Your Transmission and Jackett integrations, their passwords and keys sealed like the others', and your
Transmission destinations, each with its folder, live in the app's database, `mam.db`, so the backup of
the app's data keeps them. The only change to the database is one new column, the kind of destination
each new download went to; the downloads sent before have none.
