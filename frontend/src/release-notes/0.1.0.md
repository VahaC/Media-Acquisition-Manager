## Highlights

**This is the first build of Media Acquisition Manager, and it is a foundation rather than a
working tool.** You can open the app in your browser and see whether its server is ready. Searching,
importing your library and sending downloads are not here yet — they arrive in later updates of
0.1.0. See [What this build does](#what-this-build-does) and
[Coming in later updates](#coming-in-later-updates).

**Your media files are left alone.** Nothing in 0.1.0 moves, renames, changes or deletes a file in
your library. See [Your files](#your-files).

### Also in this release

- **Ready for other languages** — the app is in English, with its text kept apart from the code so
  translations can follow. See [Ready for other languages](#ready-for-other-languages).
- **Runs with Docker Compose** — one container, one command, nothing to configure. See
  [Running it with Docker](#running-it-with-docker).

## What this build does

- **The app shell.** The header shows the app's logo — a clapperboard with a download arrow, the
  same icon you see on the browser tab — its name and the version you are running.
- **A service status check.** The home page has a **Service status** card. It says **Ready** when
  the server and its database are working, and **Not ready** with the reason when something is
  wrong — for example, a database that has not been brought up to date. It checks again every
  minute while the page is open.

## Ready for other languages

The app is in English only for now. All of its text is kept apart from the code, so a translation
can be added later without changing the app itself. There is no language setting yet: it arrives
with the second language. Messages that come from the server, such as the reason a status check
failed, stay in English.

## Running it with Docker

The app comes as a ready-made Docker image. Put the project's `docker-compose.yml` and `deploy.sh`
in an empty folder, run `docker compose up -d` there, and open <http://localhost:8118>. There is
nothing to set up first: on its first start the app creates its database and its keys by itself and
keeps them in a Docker volume, so updating the app keeps them. To update later, run
`bash deploy.sh` in the same folder.

### Turning on access from other devices

Until signing in arrives, the app opens only on the computer it runs on, so nobody else on your
network can use it. To open it from your other devices anyway:

1. In the folder with `docker-compose.yml`, create a file named `.env` (you can start from a copy of
   the project's `.env.example`).
2. Add the line `APP_BIND_ADDRESS=0.0.0.0` to it.
3. Run `docker compose up -d` again.

Everyone who can reach that computer can then use the app, so do this only on a network you trust.

## Coming in later updates

These are planned for later updates of 0.1.0, not included in this build:

- Signing in with your own account.
- Importing your Jellyfin library, so you can see what you already own.
- Searching release sources next to your library.
- Sending the release you choose to qBittorrent and following its progress.

## Your files

This release never writes to your media folders. The only things it writes are its own: a small
database and the keys it generates on first start, both kept in its data folder. In Docker, the
example media folders in `docker-compose.yml` are mounted read-only, so the app couldn't change them
even by mistake.
